# Інформаційна система технічних заявок готельного комплексу

Курсова робота з дисципліни «Кросплатформене програмування», варіант 13.

- **Автор:** Малюна Віталій Станіславович.
- **Група:** 201-ТН.
- **Керівник:** Заїка С. О.
- **Навчальний рік:** 2026–2027.

Система призначена для обліку номерів, фахівців, технічних заявок, записів виконання та обладнання. JavaFX-клієнт звертається до сервера через HTTP; сервер повертає JSON і працює з базою MySQL.

## Можливості

- Створення, перегляд, редагування та видалення номерів, фахівців, заявок, записів виконання й обладнання.
- Послідовна зміна стану заявки: `NEW → ASSIGNED → IN_PROGRESS → COMPLETED`.
- Відхилення пропуску етапів, зворотних переходів і повторного встановлення поточного стану.
- Серверний розрахунок показника `I = 0,40 × F1 + 0,35 × F2 + 0,25 × F3`.
- Валідація введення та перевірка існування пов’язаних записів.
- Фоновий імпорт номерів та обладнання з CSV через JavaFX Task, індикатор прогресу і текстовий статус.
- Логування операцій та помилок.
- 20 модульних тестів JUnit 5.

Фактори вводяться цілими числами від 0 до 100: F1 — вплив на гостя, F2 — тяжкість несправності, F3 — вплив на доступність номера. Для значень 80, 60, 40 показник дорівнює 63.

## Архітектура та структура

JavaFX-інтерфейс використовує `HttpHotelClient`. На сервері Servlet приймає параметри, Service перевіряє предметні правила, а DAO виконує SQL через JDBC. Клієнт не має прямого підключення до бази даних.

| Шлях | Призначення |
| --- | --- |
| `database.sql` | Структура бази hotel та початкові демонстраційні дані |
| `server/pom.xml` | Залежності й складання серверного WAR |
| `server/src/main/java/ua/edu/nupp/kpp/server` | Моделі, DAO, Service, Servlet, DBUtil і RiskCalculator |
| `server/src/main/webapp/WEB-INF/web.xml` | Маршрути Servlet |
| `server/src/test/java/ua/edu/nupp/kpp/server/CourseworkTest.java` | Модульні тести |
| `client/pom.xml` | Залежності та запуск JavaFX |
| `client/src/main/java/ua/edu/nupp/kpp/client` | Інтерфейс, HTTP-клієнт, моделі та фонові задачі |
| `client/sample-data/rooms.csv` | Дані номерів для імпорту |
| `client/sample-data/equipment.csv` | Дані обладнання для імпорту |

Модулі `server` і `client` мають окремі `pom.xml`. Усі подальші команди виконуються з указаного каталогу.

## Вимоги до середовища

- JDK 21, а не лише Java Runtime.
- Maven 3; також можна використовувати Maven з IntelliJ IDEA.
- Apache Tomcat 9 для серверної частини на `javax.servlet`.
- MySQL; у локальному навчальному середовищі використано модуль MySQL у XAMPP.
- Вільний порт `8080` для Tomcat та доступ до MySQL на порту `3306`.
- Доступ до мережі для першого завантаження Maven-залежностей.

JavaFX і бібліотеки застосунку завантажуються через Maven. Перевірити версії середовища можна командами:

```bash
java -version
mvn -version
```

У результаті `mvn -version` має бути зазначено Java 21. У IntelliJ IDEA також перевірте JDK проєкту та JDK Maven Runner.

## 1 Підготовка бази даних

1. Запустіть MySQL.
2. Для **нової навчальної бази** виконайте кореневий файл `database.sql`, наприклад через вкладку «Імпорт» у phpMyAdmin.
3. Перевірте наявність бази `hotel` і таблиць `rooms`, `specialists`, `requests`, `execution_records`, `equipment`.

**Увага:** `database.sql` починається з `DROP DATABASE IF EXISTS hotel`. Його повторний запуск видаляє всі наявні дані цієї бази. Якщо дані потрібні, спочатку зробіть резервну копію; для звичайного запуску вже створеної бази повторний імпорт SQL не потрібний.

Налаштування підключення містяться у серверному `DBUtil.java`:

| Параметр | Поточне значення |
| --- | --- |
| JDBC URL | `jdbc:mysql://localhost:3306/hotel` |
| Користувач | `root` |
| Пароль | Порожній рядок |

Якщо ваша база використовує інші реквізити або порт, змініть ці значення перед складанням сервера.

SQL-файл створює два номери та двох фахівців. Заявки, обладнання і записи виконання додаються через застосунок або передбачений CSV-імпорт.

## 2 Складання та розгортання сервера

Відкрийте термінал у корені проєкту та виконайте:

```bash
cd server
mvn clean package
```

Після успішного складання з’явиться:

```text
target/server-1.0-SNAPSHOT.war
```

Складання також запускає модульні тести.

Для локального розгортання:

1. Зупиніть попередній екземпляр Tomcat, якщо він працює.
2. Скопіюйте `server-1.0-SNAPSHOT.war` до каталогу `webapps` вашого Tomcat 9.
3. Якщо замінюєте попереднє розгортання, при зупиненому Tomcat приберіть старий WAR і розпакований каталог `server-1.0-SNAPSHOT` саме цього застосунку, а потім скопіюйте новий WAR.
4. У Windows відкрийте термінал у каталозі `bin` Tomcat і виконайте:

```bat
catalina.bat run
```

У PowerShell використовуйте `./catalina.bat run`. У Linux або macOS запуск із каталогу `bin` виконується командою `sh catalina.sh run`.

Одночасно має працювати один потрібний екземпляр Tomcat на порту 8080. Якщо у XAMPP є інший Tomcat, не запускайте його паралельно на тому самому порту.

Відкрийте у браузері:

[Список номерів на локальному сервері](http://localhost:8080/server-1.0-SNAPSHOT/rooms)

Очікується JSON-масив номерів. Якщо таблиця порожня, відповідь буде `[]`.

## 3 Запуск JavaFX-клієнта

MySQL і сервер застосунку мають працювати до запуску клієнта.

Відкрийте **новий термінал у корені проєкту** та виконайте:

```bash
cd client
mvn javafx:run
```

Робочим каталогом має бути саме `client`, оскільки CSV-файли відкриваються за відносними шляхами `sample-data/rooms.csv` та `sample-data/equipment.csv`.

Адреса сервера задана у `HttpHotelClient.BASE`:

```text
http://localhost:8080/server-1.0-SNAPSHOT
```

Якщо змінено назву WAR, порт або адресу сервера, узгодьте `BASE` з фактичним розгортанням.

У вікні доступні вкладки «Номери», «Фахівці», «Заявки», «Звіти про виконану роботу» та «Обладнання». Для зміни або видалення спочатку виберіть рядок таблиці.

## 4 CSV-імпорт

Обидва файли зберігаються в UTF-8. Роздільник — крапка з комою, перший рядок — обов’язковий заголовок. Порожні рядки даних пропускаються; BOM на початку заголовка допускається.

### Номери

Файл `client/sample-data/rooms.csv`:

```csv
r_number;price;status
901;500;0
902;700;1
```

Перейдіть до вкладки «Номери» й натисніть «Імпортувати CSV». Після успішного імпорту цього файла буде повідомлено про 2 додані номери.

### Обладнання та ID кімнат

Поле `room_id` містить **значення `rooms.id`**, а не номер кімнати зі стовпця `r_number`.

Перед імпортом звірте посилання з поточною базою:

```sql
SELECT id, r_number FROM rooms ORDER BY id;
```

У демонстраційному файлі останньої версії проєкту використано ID 4 і 5, які були наявні в робочій базі. Після нового створення бази через `database.sql` початкові кімнати мають ID 1 і 2. Тому для чистої бази змініть `client/sample-data/equipment.csv`, наприклад так:

```csv
room_id;name
1;Кондиціонер
1;Телевізор
2;Холодильник
2;Кондиціонер
```

Для іншої бази використовуйте її фактичні ID. Імпорт номерів не переписує посилання в equipment.csv автоматично.

Після узгодження ID перейдіть до вкладки «Обладнання» й натисніть «Імпортувати CSV». Для наведеного файла очікується 4 додані записи.

### Прогрес і помилки

- Імпорт працює у JavaFX Task в окремому потоці.
- Кнопка відповідного імпорту блокується на час виконання.
- Прогрес і текстовий статус показують хід обробки.
- Лічильник збільшується після успішної HTTP-відповіді.
- За першої помилки імпорт зупиняється. Повідомлення містить номер рядка та кількість підтверджених записів.
- Раніше збережені рядки залишаються у базі; спільної транзакції для всього файла немає.
- Повторний імпорт може створити дублікати. Перед повтором перевіряйте вже додані записи.

Поточний розбір CSV не підтримує лапки, екранування `;` чи багаторядкові значення. Не використовуйте роздільник усередині назви обладнання. Окремої кнопки скасування у GUI немає.

## 5 Запуск модульних тестів

Виконайте з каталогу `server`:

```bash
mvn clean test
```

У IntelliJ IDEA також можна запустити `server → Lifecycle → test` у панелі Maven.

У класі `CourseworkTest` визначено 20 тестових методів:

| Група | Кількість | Зміст |
| --- | ---: | --- |
| Інтегральний показник | 6 | Відомі результати, межі, від’ємні значення, значення понад 100, NaN і нескінченності |
| Життєвий цикл | 4 | Дозволені переходи, пропуск етапів, повернення назад, повторення стану |
| Валідація моделей | 10 | Номери, фахівці, заявки, обладнання та записи виконання |

Під час підтвердженого запуску 28 листопада 2026 року отримано:

```text
Tests run: 20, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

Звіти створюються у `server/target/surefire-reports`. Для цих модульних тестів MySQL, Tomcat і JavaFX не потрібні: вони перевіряють обчислення, правила переходів і валідацію без звернення до БД. Роботу HTTP, CRUD і CSV перевіряють окремо через застосунок.

## 6 HTTP-маршрути

Базова адреса локального розгортання: `http://localhost:8080/server-1.0-SNAPSHOT`.

| Маршрут | GET | POST action |
| --- | --- | --- |
| `/rooms` | Список номерів | `add`, `update`, `delete` |
| `/specialists` | Список фахівців | `add`, `update`, `delete` |
| `/requests` | Список заявок із riskIndex | `add`, `update`, `delete`, `changeState` |
| `/executionrecords` | Список записів виконання | `add`, `update`, `delete` |
| `/equipment` | Список обладнання | `add`, `update`, `delete` |

POST-запити передають параметри як `application/x-www-form-urlencoded; charset=UTF-8`. Сервер повертає JSON. Для помилок введення передбачено HTTP 400, для інших винятків — HTTP 500 з полем `error`.

## 7 Контрольний сценарій

1. Перевірте GET `/rooms` у браузері та завантаження списків у JavaFX.
2. Створіть тестовий номер і фахівця, змініть їх дані.
3. Додайте заявку для існуючого номера з факторами 80, 60, 40. Перевірте `NEW` та показник 63.
4. Спробуйте `NEW → COMPLETED`: очікується відмова зі збереженням попереднього стану. Потім виконайте всі дозволені переходи.
5. Додайте запис виконання, змініть його текст. Зв’язок із заявкою під час редагування зберігається.
6. Додайте обладнання, змініть назву й видаліть тестовий запис.
7. Перевірте обидва CSV-імпорти на наборі, який ще не імпортувався; звірте кількість записів у клієнті та БД.
8. На копії CSV перевірте неправильний заголовок, нечислове значення й відсутній ID кімнати. Перевірте номер помилкового рядка та кількість записів, збережених до зупинки.
9. Перевірте видалення пов’язаного номера. Для прибирання тестових даних спочатку видаліть залежні записи: обладнання, запис виконання, заявку; потім фахівця та номер.

Запис виконання не створюється автоматично при переході до `COMPLETED`. Зміна стану й облік виконаної роботи є окремими операціями.

## 8 Типові проблеми

| Симптом | Що перевірити |
| --- | --- |
| HTTP 404 | Екземпляр Tomcat, назву WAR/контексту, URL, журнал розгортання та `BASE` клієнта |
| HTTP 500 | Підключення до MySQL, структуру таблиць та серверні журнали; загальне повідомлення клієнта не показує точну причину |
| Помилка імпорту обладнання на рядку 2 | Чи існує перший `room_id` з CSV у `rooms.id` |
| CSV-файл не знайдений | Робочий каталог `client` та наявність обох файлів у `sample-data` |
| Помилка JSON | Відповідність властивостей клієнтських моделей фактичній JSON-відповіді сервера |
| Помилка видалення | Зовнішні ключі: на запис можуть посилатися заявки, обладнання або записи виконання |
| Maven не знаходить Java 21 | Результат `mvn -version` і JDK Maven Runner в IDE |
| `mvn` не розпізнано в терміналі | Maven у PATH або запуск відповідної цілі через панель Maven в IntelliJ IDEA |

Для діагностики використовуйте консоль клієнта, консоль Tomcat та журнали каталогу `logs` Tomcat. Формулювання деяких внутрішніх серверних помилок ще потребує уніфікації.

## Поточні обмеження

- Звичайні CRUD-запити та початкове оновлення виконуються синхронно; фонові задачі реалізовані для CSV.
- Імпорт не видаляє дублікати та не відкочує весь файл після помилки.
- Адреси сервера й JDBC-реквізити задані у коді.
- Ролі користувачів та авторизація не реалізовані.
- Валідація статусу номера перевіряє наявність значення; окремий перелік допустимих числових кодів не заданий.
